# Internationalisation (English / Urdu, RTL)

Fully offline. No URL prefixes: `/pos` is `/pos` in every language. In-house helper (no next-intl):
the language is a per-user preference, and a routing plugin would add nothing for a desktop app.

## How the language is chosen

`apps/web/src/i18n/core.ts` (`resolveLocale`): signed-in user's `users.language` wins, then the
`mediescare_lang` cookie (login page, setup), then English. The root layout sets `<html lang dir>`
(`dir="rtl"` for `ur`) and mounts `I18nProvider`.

The switcher (`LanguageSwitcher`) sits in the top bar (`persist`, calls `PATCH /api/me`, which updates
the user through `updateUser`, so it is audited and synced, and sets the cookie), and on login/setup
(cookie only). Login also stores the user's language in the cookie.

## Files

- `en.json` (source) and `ur.json`: nested, flattened to `nav.pos`. Placeholders are `{name}`.
- `core.ts` pure logic. `messages.ts` merges Urdu over English. `server.ts` gives `getT()` / `getLocale()`.
  `client.tsx` gives `useT()` / `useLocale()`.
- `t(key, params)`; `t.has(key)` checks existence. A key missing in Urdu shows the English text. A key
  missing everywhere shows the key in development and readable words in production.
- `i18n.test.ts` fails when the two files have different keys or different placeholders.

## Font and digits

Noto Nastaliq Urdu (SIL OFL 1.1) is bundled in `apps/web/public/fonts` (woff2 400 and 700 plus the
licence) and declared in the marked i18n section at the end of `globals.css`. `public/` is copied into
the standalone output and the Electron app by `apps/desktop/scripts/prepare-web.mjs`. The `@font-face`
uses a `unicode-range` for Arabic script only, so Latin letters and digits use the Latin font and stay
Western (ADR 0002). Urdu line height is 2.1 because Nastaliq glyphs are tall.

## Convert a screen (step by step)

1. Server component: `const { t } = await getT();`. Client component: `const t = useT();`.
2. Add keys to `en.json` under a namespace named after the screen (`settings.title`, `settings.saved`).
   Reuse `common.*` for Save, Cancel, Close, Search, Print, Export, Add, Edit, Delete, Yes, No.
3. Replace every visible string (labels, buttons, headings, `aria-label`, `placeholder`, `title`,
   empty and error states) with `t('...')`. Counts and names go through `{placeholders}`; do not build
   sentences by concatenation. Use separate keys for singular and plural.
4. Add the same keys to `ur.json` with the same placeholders. Use natural Pakistani Urdu and keep common
   shop words (Stock, Invoice, POS) where staff say them. Write numbers as Western digits.
5. Replace physical Tailwind classes with logical ones: `ms-/me-`, `ps-/pe-`, `text-start/text-end`,
   `border-s/border-e`, `start-/end-`. Icons that show direction (arrows, chevrons) need `rtl:rotate-180`.
6. Keep Latin-only values (codes, barcodes, usernames, money) left-to-right (`dir="ltr"`); money and
   quantities are formatted with the existing helpers, never with Urdu digits.
7. Run `pnpm --filter @mediescare/web test` (parity test) and look at the screen in Urdu.

Server error messages come from the API in English. Translate them by mapping the error `code` to a key
on the client when a screen is converted.

## Add a language

Add the code to `LOCALES` and `dirOf` in `core.ts`, create `xx.json`, register it in `messages.ts`, add
`language.xx` to every message file, allow it in the `language` enum of `/api/me` and `/api/users/[id]`
(and the `users.language` value), add a font if its script needs one, and extend the parity test.
